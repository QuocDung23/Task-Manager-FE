## Chi tiết implement

### Chuẩn hoá data
- `ProjectMemberResponse` → `MemberItem`: `membershipId = m.id`, `userId = m.userId`.
- `BoardMemberUser` → `MemberItem`: `membershipId = m.boardMemberId`, `userId = m.id`.
- `isOwner` resolve từ `useProject(id).data?.data?.userId` / `useBoard(id).data?.data?.userId`.

### Quản trị quyền (Phase 4 — guards)
- **Owner:** badge "Owner" + icon `Shield`; ẩn toàn bộ action (dropdown role +
  nút xoá).
- **Admin cuối cùng:** `adminCount <= 1` → ẩn nút xoá + chặn demote xuống Member
  (dropdown không hiển thị cho row admin cuối — tránh khoá quản trị).
- **Member thường viewer:** `isAdminViewer=false` → chỉ xem danh sách, ẩn action.
- **Tự rời scope:** khi xoá chính mình — project: self-remove → navigate
  `/projects`; board: self-remove → đóng dialog lại.
- **Xoá có xác nhận 2 bước:** click xoá lần 1 → row chuyển "Cancel / Remove",
  tránh `window.confirm`, khớp style app.

### Realtime & cache
- Không viết thêm cache applier — dialog đọc query `useProjectMembers` /
  `useBoardMembers` (cùng query key), socket events `project:member_*` /
  `board:member_*` → cache mutation → dialog tự render lại.

### Busy-id tracking
- Dialog so sánh busy-id (pending remove/role) theo `membershipId`.
- Project: mutation key bằng `membershipId` (map trực tiếp).
- Board: mutation key bằng `userId` → wrapper resolve ngược `userId` → 
  `membershipId` từ danh sách hiện tại để khớp busy state trong row.

### Design language
- Follow sát `AddMemberDialog` hiện có: Dialog content `rounded-3xl`, lớp
  `p-1.5` + card `rounded-[calc(1.5rem-0.375rem)]`, inset highlight shadow,
  framer-motion entrance (`EASE_FLUID`, `SPRING_PRESS`, `pressHover`/`pressTap`,
  `iconHover`/`iconTap`), pill buttons, khối icon header `Users` trong khung
  primary tint.

## Cập nhật 2026-09-22 — Fix `updateProjectMemberRole` (PATCH không chạy + UI không render theo BE)

### Nguyên nhân (đã đối chiếu với BE)

1. **PATCH bị reject:** BE `PATCH /project/{projectId}/members/{memberId}`
   (`projects.router.ts`) validate body qua `updateProjectMemberRequestBody`
   = `{ roleId: z.string().uuid() }`. BE lưu role dưới dạng **UUID**
   (`roles.id @default(uuid())` trong `schema.prisma`), chỉ field `role`
   mới là tên (`PROJECT_ADMIN`…). Trước đó FE gửi thẳng tên role
   (`"PROJECT_ADMIN"`) làm `roleId` → zod reject 400 → không cập nhật DB.
2. **UI không render lại theo DB:** (a) do PATCH fail nên `onSuccess` +
   `applyProjectMemberRoleUpdated` không chạy; (b) kể cả khi cache có data,
   `MemberItem.roleId` là **UUID**, nhưng code guard/label dùng
   `roleId.endsWith("_ADMIN")` và `MEMBER_ROLE_LABELS[roleId]` → luôn ra
   `false`/"Member" → badge, `isAdminViewer`, `countAdminMembers` đều sai.

### Fix (FE-only, không sửa BE)

- `MemberItem` thêm field **`role` (tên role)**: project map từ
  `ProjectMemberResponse.role`.
- `isAdminRole` / `getMemberRoleLabel` / `countAdminMembers` giờ lấy input là
  **tên role** (`member.role`), không còn dựa vào `roleId` (UUID).
- `manage-members-project.tsx`: dựng `roleUuidByName: Map<tên → uuid>` từ
  payload members (`role` + `roleId`) rồi resolve `roleName → uuid` trước khi
  gọi mutation — body PATCH luôn là UUID hợp lệ.
- `roleIdsForScope` → đổi tên `roleNamesForScope` (đúng ngữ nghĩa đang trả).

### Điểm cần lưu ý (ngoài scope FE)

- **Board:** BE hiện chỉ mount `GET/POST /board/:boardId/members`
  (`board.router.ts`); **không có** route PATCH/DELETE member board →
  `useUpdateBoardMemberRole` / `useRemoveMemberBoard` sẽ 404 với BE này
  (plan §1 ghi "✅" là chưa đúng với code BE hiện tại). Ngoài ra
  `BoardMemberUser` cũng **thiếu field `role` (tên)** nên board không tự
  resolve được admin/tên role. Cần BE bổ sung route + DTO role name.
